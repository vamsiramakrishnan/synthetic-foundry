# KB0004417 — Applying a manual hierarchy mapping override for inventory valuation

**Category:** Data Platform › Month-end
**Applies to:** `inventory-valuation` (SVC-0001), Merchandising Hub (SYS-0002)
**Author:** R. Okonkwo, Data Platform Engineer · **Published:** 3 April 2026

> Synthetic corpus. Generated by Worldloom for evaluation purposes. Not a real company.

## When to use this

Use this article when the inventory valuation job produces no output partition and the
validation query returns SKUs with no mapped department node in the current hierarchy.

Symptom: valuation feed status `failed`, no partition for the period, and a non-zero
count from the unmapped-SKU query.

This is what happened during the March 2026 close, when 18,412 SKUs had no mapped
node and the period could not be valued.

## Cause

The legacy-to-new product hierarchy mapping is maintained manually and drifts from the
master hierarchy in Merchandising Hub. When a new department is added without a
corresponding mapping row, SKUs beneath it have no valuation rule and the job stops
rather than producing a partial valuation.

## Procedure

1. Run the unmapped-SKU validation query and record the count.
2. Export the unmapped SKUs with their legacy department codes.
3. Derive the mapping rows for the affected departments from the current range
   architecture.
4. Apply the override to the valuation staging table. **Do not write to the master.**
5. Re-run the valuation job for the period.
6. Confirm the output partition exists and the valued total is plausible against the
   prior period.
7. Record the override on the incident and notify the Group Financial Controller.

## Important

The override is **not** persisted to Merchandising Hub. The master remains stale after
this procedure, and the next period will fail the same way unless the mapping is
corrected at source.

There is no registered owner for the mapping table, so raise correction of the master
against Merchandising Systems explicitly rather than assuming it will be picked up.
