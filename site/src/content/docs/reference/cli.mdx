One line per command, grouped by what you are doing. Key flags only; every
command takes `--help`. Commands whose output an agent should parse take
`--json`. The repository's generated reference
(`.claude/skills/worldloom/references/commands.md`) lists every option and is
regenerated by `worldloom docs`, so it cannot drift from the CLI.

## Building

| Command | What it does |
| --- | --- |
| `worldloom build` | Generate a world from a seed, then validate it. |
| `worldloom mosaic` | Build several companies at once, as unlike each other as the rules allow. |
| `worldloom demo <NAME>` | Build a bundled demo corpus, validate it, export it. |
| `worldloom twin <CORPUS>` | Rebuild with one recorded value replaced; measure the delta. |

`build` flags worth knowing: `--seed`, `--out`, `--archetype`, `--periods`,
`--incident`, `--timeline quiet|steady|turbulent`, `--comparatives` and
`--trend` for history, `--estate small|medium|large`, `--policies core|full`,
`--hiring N` and `--reviews N`, `--messiness`, `--locale`, `--facet`,
`--spec`, `--pack`, `--physics`, `--narrate` for the built-in deterministic
writer, `--replay <CORPUS>` to rebuild from a ledger, `--section-omission` and
`--outline-synthesis` for derived outlines, `--conversations` for the
knowledge ledger, `--actors scripted|agent`.

`mosaic` flags: `-n`, `-e retail|banking|insurance`, `--probe`,
`--shard-count`/`--shard-index`, `--resume`, `--describe` to plan without
building.

## Narrating and planning

| Command | What it does |
| --- | --- |
| `worldloom narrate requests <CORPUS>` | Emit the prose requests an agent needs to answer. |
| `worldloom narrate accept <CORPUS>` | Validate prose and commit it, or report every violation. |
| `worldloom plan requests <CORPUS>` | Emit artifact-shape requests, one level above prose. |
| `worldloom plan accept <CORPUS>` | Validate proposed shapes against the grammar. |
| `worldloom compose requests <CORPUS>` | Emit the request for authoring the technology estate. |
| `worldloom compose accept <CORPUS>` | Validate an authored estate against the graph. |
| `worldloom act requests <CORPUS>` | Emit the next actor decision an employee has to make. |
| `worldloom act accept <CORPUS>` | Validate a decision and commit it, or name the rule it broke. |

Every `accept` takes `--from <FILE>`, `--model-id`, and `--json`.

## Rendering

| Command | What it does |
| --- | --- |
| `worldloom render <CORPUS>` | Render an existing corpus into files. `-f` repeatable; `--profile audit\|reader\|filing`. |
| `worldloom formats` | List the renderers this installation has. |
| `worldloom workspace <CORPUS>` | Lay the corpus out as a shared drive. `--noise none\|lived_in\|neglected`. |
| `worldloom present describe` | Every presentation profile and knob. |
| `worldloom present brief <CORPUS>` | The context needed to author a profile. |
| `worldloom present lint <SPEC>` | Check a profile you wrote; name every finding. |

## Measuring

| Command | What it does |
| --- | --- |
| `worldloom validate <CORPUS>` | Check coherence. Any failure is a defect. |
| `worldloom evaluate <CORPUS>` | Score retrievers against the evaluation set. `--retriever bm25\|tfidf\|embedding\|both\|all`, `-k`, `--vectors`. |
| `worldloom stats <CORPUS>` | What the corpus contains. `--against` diffs two corpora. |
| `worldloom topology <CORPUS>` | Blast radius and gates: what nothing routes around. |
| `worldloom series <CORPUS>` | Trend, season, and the periods neither explains. Needs a history. |
| `worldloom diversity <CORPUS>` | How structurally varied the batch is. `--near-duplicates`, `--effective`, `--across`. |
| `worldloom status <CORPUS>` | The stage the corpus is at, and the exact next command. |
| `worldloom inspect <CORPUS>` | List facts, events, artifacts, evals, or lore. |
| `worldloom evals export <CORPUS>` | The evaluation set as JSONL, for scoring an external system. |

## Fleets

| Command | What it does |
| --- | --- |
| `worldloom spaces` | The configuration space: 12 axes. `--cover -t 2` plans a fleet; `--holes` scores one. |
| `worldloom fleet qualify <DIR>` | Measure a fleet and rule on its purpose. Exit 1 if not qualified. |
| `worldloom fleet curate <DIR>` | One champion per niche; every reject named. |

Both `fleet` commands take `--purpose challenge|counterfactual`.

## Authoring

| Command | What it does |
| --- | --- |
| `worldloom archetypes` | The company shapes `build --archetype` accepts. |
| `worldloom pack template <ENGINE>` | A minimal valid pack to start from. |
| `worldloom pack check <SOURCE>` | Validate a pack and lint its lore against the engine. |
| `worldloom pack spec` | The company-specification schema. `--template` writes a starter. |
| `worldloom pack facets` | Every facet dimension and what each value commits to. |
| `worldloom pack locales <NAME>` | A jurisdiction's conventions. |
| `worldloom pack messiness` | The archive-keeping profiles. |
| `worldloom pack params <PREFIX>` | Every physics range a pack may override. |
| `worldloom pack profiles` | The trading years a pack may pick by name. |
| `worldloom pack targets <ENGINE>` | The lore targets an engine consults. |
| `worldloom pack texts <ENGINE>` | The surface-text templates a pack may override. |
| `worldloom pack landscapes <NAME>` | The estate vocabularies `--estate` grows from. |
| `worldloom pack export <OUT>` | Keep a mosaic world or settled probe as a pack. |
| `worldloom probe open` | Start a physics probe from a premise. `-p`, `--depth`. |
| `worldloom probe next <PATH>` | The next question, with its bounds. Exit 3 when settled. |
| `worldloom probe accept <PATH>` | Check one answer against the graph. |
| `worldloom probe show <PATH>` | The constraint graph as it stands. |
| `worldloom probe worlds <PATH>` | The worlds the probe allows, furthest apart. |
| `worldloom probe resolve <PATH>` | Turn a settled graph into a physics file. |

## Everything else

| Command | What it does |
| --- | --- |
| `worldloom actors <CORPUS>` | The actor execution ledger. `--observations`, `--rejected`. |
| `worldloom mcp` | Serve the read-only measurements as MCP tools over stdio. |
| `worldloom docs` | Regenerate the command reference from the CLI. `--check` for CI. |
| `worldloom version` | Print the installed version. |
