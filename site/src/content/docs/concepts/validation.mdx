---
title: Validation
description: Check corpus coherence, interpret advisories, and decide what still needs evaluation.
---

Run validation after generation, accepted narration, and rendering:

```bash
worldloom validate ./corpus
```

The verdict concerns the configured coherence rules. A passing verdict does
not establish enterprise breadth, document realism, rendering quality, or
successful retrieval. Keep those results separate.

## What the checks compare

| Check family | Compared values |
|---|---|
| Arithmetic | Totals, components, variances, rates and their canonical facts |
| Chronology | Artifact knowledge cutoffs, fact validity and entity lifetimes |
| Identity and access | Authors, approvers, reporting relationships and permissions |
| Artifact coverage | Each intent's required facts and its own compiled artifact |
| Rendered output | Manifest files, declared figures and chart inputs |

Artifact coverage is checked per document. A fact in one workbook cannot
satisfy another document's requirement. This catches empty or missing output
that a corpus-wide union of facts could conceal.

## Read the result

Coherence violations fail the verdict. Advisories describe other measured
properties and do not count as violations. For example, reachability can show
that named people or systems never appear in readable evidence even when all
existing references are valid.

Check counts depend on the recipe, revision, artifact set, and render stage.
Use the count from the actual run; a larger count is not a quality score.
The [quickstart](/worldloom/getting-started/quickstart/) records one fixture's
observed counts with its source revision.

## Decide the next check

| Question | Next step |
|---|---|
| Does the corpus cover the intended business functions? | Enterprise admission audit in the repository guides |
| Can a reader use the rendered files? | Open the files and inspect layout, labels, formulas and citations |
| Can a retriever answer the generated cases? | [Evaluation](/worldloom/concepts/evaluation/) |
| Do accepted inputs replay? | [Determinism](/worldloom/concepts/determinism/) |
| Does the agent complete a multi-step task? | Execute and grade the agent workflow against its expected effects |

## Resolve a failure

Use the reported rule and artifact or fact identity to find the inconsistent
input or transformation. Correct that cause and rerun validation. Do not
change a fixture or relax an invariant solely to make the current result pass.
An intentional rule change needs a behavioral test and an explicit compatibility
decision.
