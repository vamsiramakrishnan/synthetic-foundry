---
title: Build your first corpus
description: Generate a local corpus, open its rendered files, validate its claims, and measure retrieval without a model service.
---

This guide produces a local corpus with deterministic sample prose. It requires
no model service or cloud credentials. Complete
[installation](/synthetic-foundry/getting-started/installation/) with the `all`
extra so all five document renderers below are available.

## 1. Build one episode

```bash
worldloom build --seed 8128 --incident --narrate --out ./corpus
```

The example is an omnichannel retailer's month-end close with an operational
incident. `--narrate` fills prose using the built-in deterministic provider.
It is useful for inspecting the pipeline; it does not measure production
writing quality.

## 2. Render files you can open

```bash
worldloom render ./corpus -f xlsx -f docx -f pptx -f pdf -f markdown
```

Open `corpus/artifacts/`. Then inspect the records behind those files:

```bash
worldloom inspect ./corpus --facts
worldloom inspect ./corpus --artifacts
```

`facts.jsonl` holds canonical facts. `artifact-intents.jsonl` states what the
artifacts should contain. `artifact-manifest.jsonl` links rendered outputs to
their provenance. [Corpus anatomy](/synthetic-foundry/reference/corpus-anatomy/).

## 3. Check consistency and retrieval separately

```bash
worldloom validate ./corpus
worldloom evaluate ./corpus --retriever both
```

Validation checks identities, chronology, arithmetic, and declared artifact
contracts. Evaluation compares BM25 and TF-IDF retrieval against `evals.jsonl`.
Passing validation does not mean a retriever answers every question.

A local run of this sequence on revision `28da948` produced 615 facts, 16
artifact intents, and 51 evaluation cases, and passed 8,877 coherence checks
after rendering. Both lexical baselines failed all expected-abstention and
temporal-state cases. These are observations for that fixture and revision,
not fixed counts or product-wide performance claims.

## 4. Add a business-system or drive view

```bash
worldloom render ./corpus -f jira -f confluence -f servicenow
worldloom workspace ./corpus -o ./drive
```

The drive export includes a folder layout and `permissions.jsonl`. The system
bundles are local test data; these commands do not publish to live tenants.

## 5. Find the next incomplete stage

```bash
worldloom status ./corpus
```

Use its next action when a stage is missing. If a renderer dependency is absent,
`worldloom doctor` names the relevant installation extra.

## Next: replace test prose with authored prose

Create a separate corpus **without** `--narrate` so narration requests are pending:

```bash
worldloom build --seed 8128 --incident --out ./authored-corpus
worldloom narrate requests ./authored-corpus -o requests.json
```

An external writer reads `requests.json` and produces `responses.json` under
the [narration contract](/synthetic-foundry/guides/narration/). The library does
not call a model on your behalf. Then accept, render, and validate:

```bash
worldloom narrate accept ./authored-corpus --from responses.json --model-id your-writer
worldloom render ./authored-corpus -f xlsx -f docx -f markdown
worldloom validate ./authored-corpus
```

Acceptance can reject unsupported claims or bare figures. Fix the reported
violation and resubmit; preserve the accepted ledger for replay.

## Next: broaden the company

The default close is a bounded episode. A full enterprise evaluation needs
explicit choices about processes, periods, systems, people, artifact families,
and distractors. Use [enterprise corpus generation](https://github.com/vamsiramakrishnan/synthetic-foundry/blob/main/docs/enterprise-corpus.md)
to plan those axes before increasing volume.
